# AI 味模式清单（编号对照 + 强度分级）

> 模式 3「去 AI 痕迹」的权威清单。从 ../../modes/humanization.md 外移，逐条对照检查时读这份。

## 为什么要编号

「有 AI 味」本身不是可执行的判据，形容词无法指导改写。这里把 AI 写作痕迹拆成六类、32 条编号模式，每条给**编号 + 识别特征 + 改法**，逐条对照即可，不靠语感。

语言模型的写法是：永远选语料里最可能的下一步，默认落在适用面最广的答案上。真人作者是写给一个特定读者和一件具体的事的，所以他的选择是不均匀、具体的。下面每条模式都是这种「默认选择」的一种形态。

由此得到两条判定原则：

1. **留下来的每一句，都要给读者带去他原本没有的信息**（来自文本前文，或来自对话上下文）。复读一遍已知内容的句子就是废话。
2. **征兆的严重度，按「认真的作者多不会故意这么写」的程度计**。

## 强度分级怎么读

| 标记 | 含义 |
| ---- | ---- |
| **强** | 见一次就该改。这是模型默认选择，人不会这么写 |
| **弱** | 本身可能是正常作者风格。**必须同一段落里还有别的征兆才动手**。误伤弱项 = 把作者本人的声音当 AI 味删掉 |
| **需上下文** | 只在能看到对话上下文、或文本明显是回复时动手；否则问用户或原样保留 |

弱项单独出现是正常写作。例如真人里也用破折号（很多编辑和记者都用），也用被动（技术文档里被动常常更准），也用弯引号（多数编辑器自动替换）。**几个征兆同时出现才是信号**——靠语感判断准确率不比抛硬币高。

## A. 摆架子而不陈述

模型在宣告重要性和表演坦诚，而不是补一个事实。当前模型文本里最频繁、最强的征兆，见一次就改。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| A1 | 否定式对举 | 强 | 「不是 X，而是 Y」「不仅仅是……更是」「这不只是关于 X，而是关于 Y」；拆成两句的变体「这并不意味着 X。这意味着 Y」；短否定收尾「……，不必猜」 | 直接说结论。仅当否定那半在纠正读者真持有的误解、或两半各有信息时保留对举 |
| A2 | 单行收尾与碎句排比 | 强 | 独立成段的一句复述上段（「这才是真正的收获」「这一点很重要」「再读一遍」）；例证或数字后跟一句「这说明了……」「信息很清楚：」；连续碎句（「没有审美先验。没有怀旧。」）；句中单词全大写或逐字加点 | 删掉复读上段的收尾句；例证自己能说明的就别替它解释；碎句并成一句带具体主张的话。收尾句带来例证没有的新事实或后果时保留 |
| A3 | 深刻金句 | 强 | 「真正的问题在于」「归根结底」「本质上」「真正重要的是」「更深层的问题是」「X 是 Y 的语言」「X 变成了陷阱」「X 是一种货币」 | 换成具体主张，剥掉伪装成洞见的修辞外壳 |
| A4 | 铺垫式开场 | 强 | 「让我们深入」「今天我们来聊聊」「先说清楚」「接下来我们看看」「话不多说」「说实话？」；独立的坦诚开场白后接一个常规主张 | 整段铺垫删掉，直接给主张。句中出现的「说实话」不算；判据是它作为**独立开场白**出现在平常主张前面 |
| A5 | 无对象的辩论 | 强 | 「这不是（主要）关于」「我不是说」「别误会」「需要说明的是」「有些人可能会认为……但是」「一个显而易见的方法是」「你可能觉得……但」 | 删掉对没人提出的反对意见的回应；里面若含真主张就只留主张。文中真正归因并完整回答的反对意见、读者真会权衡的选项，保留。多个互不相关的否认接连出现，信号强于单个 |
| A6 | 谄媚语气 | 强 | 「好问题！」「您说得完全正确」「太棒了」；不假思索的赞美（「令人惊叹」「无缝衔接」） | 删掉赞美，把事实当事实说 |
| A7 | 填充短语 | 强 | 「为了实现这一目标」→「为了实现这点」；「由于下雨的事实」→「因为下雨」；「在这个时间点」→「现在」；「值得注意的是，数据显示」→「数据显示」 | 砍掉外壳，只留动词和名词 |

## B. 按规则套的节奏

句式和标点到处套用，不管语义是否需要。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| B1 | 强行三段式 | 强 | 观点凑成三组显得全面；三个平行例；三个短事实后接一句教训 | 逐项检查是否各有独立信息；没有就合并，或改用两项、四项。语义真需要三项时保留 |
| B2 | 同义反复换词 | 强 | 同一个人在同一段里被叫做「主人公」「主要角色」「中心人物」「英雄」；同一个概念反复换说法 | 选定一个说法并保持。同义替换是模型为避重复而做的机械动作，不是作者的风格选择 |
| B3 | 句首重复 | 强 | 连续几句以同一主语开头（常是「他」「她」「我们」）；整段句式被逐句复制 | 合并句子、换主语、或以动作开头。禁的是**复制**；为节奏故意重复（排比、短句连击）保留 |
| B4 | 破折号当万能连接 | 弱 | 用「——」「 – 」「 -- 」连接本该说清关系的两个分句；每段都有一处 | 换成句号、逗号、冒号或括号，或重写这句。代码块、行内代码、命令、路径、URL 里的破折号不动 |
| B5 | 限定词堆叠 | 弱 | 「可以说」「也有可能」「或许可以」「某种程度上」「这只是一个推测」层层叠加 | 只在原文确实支持、且语义需要时保留。范围声明、法务与安全提示、真实的自我更正保留。「也许」「倾向于」这类日常模糊词不是 AI 味 |
| B6 | 连字符复合形容词 | 弱 | 名词前的复合修饰词一律带连字符：高质量、众所周知、实时、面向客户 | 名词前保留（`高质量的报告`），名词后去掉（`报告的质量很高`）。词典固定写法（第三方、跨职能）保留 |
| B7 | 被动语态与主语缺失 | 弱 | 藏起谁在做：无人称句「结果会被自动保存」；无主语片段 | 施动者明确时改主动。不许一刀切禁被动 |
| B8 | 虚假范围 | 弱 | 「从 X 到 Y」但 X 和 Y 不在有意义的尺度上（如「从初学者到专家」配一个具体单点功能） | 换成真实的两端；没有真实两端就直说 |

## C. 通胀与借来的权威

底下的事实通常是对的。留下事实，剥掉包装。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| C1 | 通用 AI 词汇 | 强 | 此外、至关重要、深入探讨、彰显、凸显、赋能、协同、生态、格局（抽象名词）、闭环、抓手、复盘、心智、护城河、深耕、沉淀 | 换成平实说法。**本表之外的一个正式用词本身不构成 AI 味**；但这一组里的词成堆出现（每段两三个）时不必犹豫 |
| C2 | 意义吹大 | 强 | 三个尺度：① 短语层「标志着……的重要节点」「体现」「彰显」「为……奠定基础」「不断演变的格局」「不可磨灭的印记」；② 固定套段「尽管面临若干挑战」「挑战与展望」「未来展望」「尽管存在这些挑战……依然蓬勃发展」；③ 寄语式结尾「未来一片光明」「令人兴奋的时代即将到来」 | 留下事实，删掉意义。结尾停在最后一个具体事实上；原文有真实规划就写规划；②③ 整段删 |
| C3 | 模糊归因 | 强 | 「行业报告显示」「观察者指出」「专家认为」「一些批评者认为」「多个来源显示」，而正文没给具名来源 | 换成原文给出的具名来源和它实际说的内容；没有就删掉这句 |
| C4 | 借来的知名度 | 强 | 「据《纽约时报》、BBC 报道」「被多家主流媒体报道」「活跃于社交平台，粉丝超过 N 万」 | 有具名来源就写出来；没有就删。**缺少引用本身不是 AI 味**——多数写作本来就没引用 |
| C5 | 销售文案 | 强 | 坐落于、位于……的中心、丰富的（比喻义）、深厚的、承载着、焕然一新、令人叹为观止、必打卡 | 说清楚这个东西是什么 |
| C6 | -ing 挂件 | 强 | 句末挂一个现在分词短语给简单事实加深度：突出了、彰显了、确保了、反映了、象征着、助力了、体现了 | 留事实，挂件只有在原文支持时才留。给句子加了具名主语（「某某强调了……」）也不因此成立 |
| C7 | 回避「是/有」 | 强 | 「作为」「代表着」「发挥着……作用」「拥有」「具备」「提供」代替「是」「有」 | 用「是」「有」 |
| C8 | 模糊关系 | 强 | 「与……相关」「有关联」「挂钩」而不说清是什么关系（任职？参与？投资？） | 写成原文给出的具体关系。原文没说就保留模糊说法，**不要替它编一个** |

## D. 按规则套的格式

模板和可视化编辑器会产出干净排版。征兆是每一项都加了装饰。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| D1 | 粗体当装饰 | 强 | 没有理由的粗体；每个列表项都粗体 | 删粗体 |
| D2 | 竖列项目符号带粗体标签 | 强 | `- **用户体验：** 用户体验有了显著提升` | 标签本身不带信息时，改写成一句散文说清三件事 |
| D3 | 装饰性标题 | 强 | 标题或列表项带 emoji / 箭头当装饰；节与节之间插横线；文档开头用一级标题重复自己的标题；为效果起的标题（「一屏之内看完决策」） | 去掉装饰和横线，标题只出现一次；标题改成说明这节装什么（「六个选项的对比」）。中文不涉及英文标题大写问题 |
| D4 | 弯引号 | 弱 | 目标格式或作者原文用直引号，却出现弯引号 “ ” 「」 | 统一成目标格式的引号 |

## E. 对话与草稿残留

直接删。不需要重写。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| E1 | 聊天套话 | 强 | 希望对您有帮助、好的问题！、当然！、需要我继续吗？、您想要我……吗？、以下是 | 删掉外壳，保留内容。这是清单里**最确定**的一条，也最容易在包裹真实内容时被漏掉 |
| E2 | 知识截止声明与猜测填补 | 强 | 截至 [日期]、根据我最后的训练更新、具体细节有限/稀缺、公开资料未见、在所提供的信息中、可能（生长于/就读于）、据称 | 写明来源没说什么，或删掉这句。**不要用推测填坑** |
| E3 | 标题后重复首句 | 强 | 标题后跟一个单行段落把标题再说一遍才进正文 | 删掉那一句 |
| E4 | 写文档而不是写主题 | 弱 | 描述这次改写替换了什么（「本函数用于替代之前遍历所有条目的做法」）；交代资料来源与工作过程（「以下数据来自各厂商公开定价，无法确认的已标注而非猜测」）；复述读者已经看得见的版面（「下表对比了……」「本节按负责人组织」） | 版本沿革只留在变更日志、发布说明、迁移指南里；保留读者能追溯的来源署名，删掉工作过程交代；只留会改变读者行动的提醒；只有读者无法自行推断的约定才写，且只写一次 |

## F. 写错了读者

模型写给一个「不共享任何上下文」的读者，因为这适用面最广。而对话里的回复，读者早就知道背景了。

| 编号 | 模式 | 强度 | 识别特征 | 改法 |
| ---- | ---- | ---- | ---- | ---- |
| F1 | 复述读者已知的背景 | 需上下文 | 短回复先重述问题、再走一遍诊断、再摆证据，结论放在最后；把对方已经写过的背景重讲一遍；把证明方案可行的命令或数据塞进回复 | 结论先行，只留会改变对方是否同意的推理——通常是一个对方缺的事实和执行所需的链接。诊断和可行性论证留给后续的工单或文档 |

> 判据：能看到对话上下文、或文本明显是回复时才动这一条。判断不了就问用户，或原样保留。

## 何时不动手

每条模式都描述一种默认选择，**人可以故意这么写**。以下情况放过：

- 引文、标题、专有名词、或正在讨论该短语本身的段落里，命中了监视词不算
- 信件或评论的称呼与落款早于聊天机器人
- 2022 年 11 月 30 日之前的文本不当作 AI 写
- 保留承载作者声音的细节：具体罕见的细节（一个真地址、一句怪引用、「那个在我牙医楼上开诊所的律师」）；矛盾与未解的张力（「我觉得这大体是好事，但它让我不安，而且我说不清为什么」）；有年代感的梗和圈内话；作者能解释的第一人称选择；真实的题外话与自我更正
